# MLVH — My Little Voice Helper

Маленький голосовой помощник: спрашиваете текстом — DeepSeek отвечает, MLVH читает ответ вслух.
Голос настраивается прямо в окне: тембр, темп, громкость, тон.
Может читать файлы в разрешённых папках, искать в интернете и вызывать
инструменты MCP-серверов — см. «Агент: чтение файлов», «Агент: интернет»,
«Агент: MCP».

Текущая версия — **0.5.0**; что менялось — в [CHANGELOG.md](CHANGELOG.md).

## Что нужно

| Компонент | Зачем | Нужен ли ключ |
|---|---|---|
| DeepSeek API (`deepseek-flash`) | сами ответы | **да**, ключ с platform.deepseek.com |
| Edge TTS (Microsoft) | синтез речи | нет, бесплатно |
| PySide6 | окно | нет |

Без ключа DeepSeek программа запускается, но отвечать не сможет: кнопка «Отправить»
предложит ввести ключ. Голос при этом работает — кнопка «Проверить голос».

## Установка

```powershell
cd D:\projects\MLVH
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy config.example.json config.json
```

Ключ: скопируйте `.env.example` в `.env` и впишите `DEEPSEEK_API_KEY=sk-...`,
либо нажмите в окне «Ввести ключ» — он сам допишется в `.env`.

`config.json` и `.env` в репозиторий не попадают: там личные настройки и ключ.

## Запуск

```powershell
python main.py                 # окно
python main.py --no-voice      # окно без озвучки
python main.py --version       # версия
python main.py --mic-test      # 3 секунды с микрофона: уровень и файл
python main.py --transcribe a.wav   # распознать готовый wav
python main.py --ask "Что в sample.txt?" --read-folder D:\docs   # агент в консоли
python main.py --ask "Сколько строк кода (.py и .toml)?" --read-folder D:\docs --agent-rounds 40
python main.py --ask "Найди в интернете курс доллара" --browse   # агент ищет в сети
python main.py --list-voices   # список русских голосов Edge
python main.py --say "Привет!" --voice ru-RU-SvetlanaNeural --rate 10
```

Или двойным щелчком по `run.bat` (запускает без чёрного окна консоли).

## Рекомендуемая конфигурация

Если не хочется разбираться в настройках — вот набор, который лучше всего
показал себя на практике. Это только совет: программа полностью работает и на
умолчаниях, а поменять можно что угодно и когда угодно.

| Что | Значение | Где менять |
|---|---|---|
| Движок голоса | **Silero v5** | панель «Голос» → «Движок» |
| Голос | **Ксения (жен.)** | там же, «Голос» |
| Движок распознавания | **faster-whisper**, модель **medium** | панель «Микрофон» → движок и «Модель» |

Почему так:

- **Silero v5** — локальный движок: точное произношение, правильные ударения,
  работает без интернета. Голос Ксении в нём звучит живее остальных. Нужна
  установка: `.\install_silero.ps1`. Веса под CC BY-NC 4.0 — для
  некоммерческого использования. В списке голосов два похожих пункта: берите
  **«Ксения (жен.)»**, а не «Ксения (жен., старая)».
- **whisper medium** — заметно точнее `small` (умолчание) на именах, терминах
  и числах. Плата: модель ~1.5 ГБ и больше времени на распознавание. На
  видеокарте разница почти незаметна, на CPU — ощутима; там лучше остаться
  на `small`.

Настройки сохраняются в `config.json` сами, руками ничего править не нужно.
Модель whisper скачается при первом использовании в `models\whisper\`.

> **Распознавание речи — экспериментальная функция.** Это касается любого
> движка и модели: оно работает, но может путать слова, терять начало фразы и
> не срабатывать на спецслово. В следующих версиях качество, скорее всего,
> заметно вырастет. Текстовый ввод при этом всегда доступен и полностью
> надёжен.

## Характеры

Характер — это связка «системный промпт + пресет голоса». Переключается в правой
панели, там же «Изменить…» и «Сброс».

| id | Название | Голос | Темп / тон |
|---|---|---|---|
| `elvi` | ✨ Элви (по умолчанию) | Svetlana | +10 % / +30 Гц |
| `helper` | 🙂 Помощник | Dmitry | 0 % / 0 Гц |
| `anime` | 🌸 Аниме-тян | Svetlana | +12 % / +45 Гц |
| `mentor` | 🎓 Наставник | Dmitry | −5 % / −10 Гц |
| `ironic` | 😏 Сарказм | Svetlana | 0 % / −10 Гц |
| `custom` | 🎛 Мой голос | ваши настройки | — |

```powershell
python main.py --list-personas
python main.py --persona anime
python main.py --persona anime --say "Ня! Проверка голоса."
```

При смене характера история диалога очищается (это другой собеседник), а в чат
пишется приветствие. Правки сохраняются в `config.json`; «Сброс» возвращает
встроенный вариант. Старый конфиг без характеров превращается в «Мой голос»,
так что настройки не теряются.

Имя характера используется и в чате: ответы подписываются им (`Элви: …`),
а не «MLVH». Приветствие при старте тоже берётся из профиля.

### Свои профили

В блоке «Характер» есть «Добавить» и «Удалить»:

- **Добавить** — открывает тот же диалог с пустым именем; `id` выдаётся
  автоматически (`custom`, `custom-2`, …), профиль сразу сохраняется в `config.json`
  и становится активным.
- **Удалить** — доступна только для своих профилей; встроенные защищены.
  После удаления включается «Помощник».
- **Сброс** — только для встроенных: возвращает исходный промпт и пресет.

Профиль можно добавить и руками — допишите объект в массив `personas` в
`config.json` с уникальным `id`. Обязательные поля: `id`, `name`, `prompt`;
остальные (`emoji`, `voice`, `rate`, `volume`, `pitch`, `max_speak_chars`,
`greeting`) имеют значения по умолчанию.

**Про «анимешность».** Edge TTS не умеет эмоции и стили — только темп, громкость
и тон. Поэтому «тян» получается из женского голоса Svetlana с поднятым тоном
(+30…+50 Гц) и, главное, из манеры в промпте. Настоящий аниме-тембр требует
другого движка (Azure со стилями, Silero/Piper локально или клонирование голоса).

### Текст перед синтезом

Для локальных движков (Silero, Chatterbox) текст готовится заранее —
`app/text_norm.py`:

- числа прописью: «15 %» → «пятнадцать процентов», «5 км» → «пять километров»;
- годы в правильном падеже: «в 2024 году» → «в две тысячи двадцать четвёртом году»;
- «21 тысяча» → «двадцать одна тысяча» (согласование);
- сокращения: «т.д.» → «так далее», «т.е.» → «то есть».

Для Edge нормализация не нужна — он сам читает цифры правильно.

### Если кусок не озвучился

Раньше сбой куска приводил к молчаливому пропуску — середина ответа исчезала.
Теперь:

1. при ошибке синтеза — повтор (2 попытки);
2. при обрыве (звук короче текста на четверть) — текст делится пополам
   и синтезируется заново (до двух уровней дробления);
3. если не вышло — кусок читается запасным голосом Windows (SAPI) и
   вставляется в очередь на своё место, а в чат пишется предупреждение.

Проверено на имитации отказа: три куска из трёх прочитаны SAPI, 8.2 с звука,
ничего не потеряно.

## Голосовые движки

Движок переключается в панели «Голос» → «Движок». Если локальный движок не
установлен, MLVH работает как раньше на Edge — ничего не ломается.

| Движок | Где работает | Произношение | Эмоции | Установка |
|---|---|---|---|---|
| **Edge TTS** (по умолчанию) | облако, нужен интернет | отличное | нет | уже стоит |
| **Silero v5** (опционально) | локально, офлайн | отличное, с ударениями | низкие | ~50 МБ + модель 139 МБ |
| **Chatterbox** (опционально) | локально, офлайн | слабое | да + клонирование голоса | ~5 ГБ |

### Silero v5 — правильный русский локально

Быстрый и точный по произношению: расставляет ударения и различает омографы
(«за́мок» / замо́к). Голоса: Бая, Ксения, Айдар, Евгений. Интонация ровная —
это «диктор», а не «актёр». Лицензия CC BY-NC 4.0: **не для коммерции**.

```powershell
.\install_silero.ps1
```

Модель (139 МБ) скачается при первом синтезе в `models\silero\`. Если у
`models.silero.ai` просрочен сертификат, MLVH скачает файл без проверки цепочки
и предупредит в логе.

Замеры на RTX 3070 Ti: первый звук **1.2 с**, весь ответ — быстрее реального
времени (19 с речи синтезируются за ~3 с).

### Chatterbox — локальный живой голос

MIT-лицензия, русский язык, 23 языка, эмоции и клонирование тембра по образцу.

**Установка** (один раз):

```powershell
.\install_chatterbox.ps1
```

Скрипт поставит `requirements-chatterbox.txt` (torch 2.6 + CUDA ~2.5 ГБ).
Модель (~2 ГБ) скачается при первом озвучивании в `models\` внутри проекта.

**Образец голоса.** Chatterbox копирует тембр из аудио-образца. Если файл не
выбран (кнопка «Образец голоса…»), MLVH автоматически сделает образец из
текущего Edge-голоса — то есть тембр останется привычным, а живость добавит
локальная модель. Образцы кэшируются в `models\references\`.

**Живость** (ползунок 0–100 %) — параметр `exaggeration`: выше — эмоциональнее
и быстрее, ниже — ровнее и спокойнее. **Похожесть** — `cfg_weight`: выше —
чётче и ближе к образцу.

**Ограничение длины куска.** Chatterbox обрывает русский текст **непредсказуемо**:
даже 80 символов иногда дают 2.5 с звука вместо ожидаемых 5.7. Это слабость
русского в 0.5B-мультиязычной модели, а не длина как таковая. Поэтому MLVH:

- режет текст мелко (45 / 75 / 95 символов);
- сверяет длительность результата с ожидаемой (~14 символов в секунду);
- при обрыве делит кусок пополам и синтезирует заново;
- если не вышло — читает кусок голосом Windows и пишет предупреждение в чат.

**Скорость.** Замеры на RTX 3070 Ti (8 ГБ), ответ 230 символов:

| Движок | Первый звук | Весь ответ | Кусков |
|---|---|---|---|
| Edge | 1.2 с | 2.5 с | 2 |
| Silero | 1.0 с | 3.0 с | 2 |
| Chatterbox | 6–7 с | 23–31 с | 6–7 |

Chatterbox в 5–10 раз медленнее и всё равно иногда спотыкается на русском.
Практический вывод: **для обычных ответов берите Silero или Edge**, Chatterbox
включайте ради эмоций и характеров вроде «Аниме-тян».

**FP16 не помогает.** Принудительный `.half()` на этой карте дал 1.27 шага
генерации в секунду вместо 36 — в 30 раз медленнее. Опция есть
(`chatterbox_fp16`), но по умолчанию выключена.

**Водяной знак.** По умолчанию отключён: на потоковых кусках файл сразу
удаляется, метка не нужна. Включается через `chatterbox_watermark`.

Модель грузится в фоне сразу при открытии окна, так что к моменту первого
вопроса она обычно уже готова. На чистом CPU синтез непригоден: замер на
Ryzen 7 5800X дал ~51 с на короткую фразу.

**Если что-то не так:**

- `'NoneType' object is not callable` при загрузке модели — не хватает
  `pkg_resources`/`onnxruntime` (водяной знак perth). Лечится:
  `pip install "setuptools<81" onnxruntime`.
- `torch: 2.6.0+cpu` — поставилась CPU-сборка. Для GPU:
  `pip install torch==2.6.0 torchaudio==2.6.0 --index-url https://download.pytorch.org/whl/cu124`

**Медленный интернет: установка CUDA вручную.** Скачайте два файла (Python 3.13,
Windows x64) в папку `wheels\`:

- `torch-2.6.0+cu124-cp313-cp313-win_amd64.whl` — ~2.4 ГБ
  <https://download.pytorch.org/whl/cu124/torch-2.6.0%2Bcu124-cp313-cp313-win_amd64.whl>
- `torchaudio-2.6.0+cu124-cp313-cp313-win_amd64.whl` — ~4 МБ
  <https://download.pytorch.org/whl/cu124/torchaudio-2.6.0%2Bcu124-cp313-cp313-win_amd64.whl>

Затем:

```powershell
.\install_torch_cuda.ps1
```

Скрипт поставит их локально (`--no-index`), без обращения к сети. Вместо `cu124`
можно взять `cu126` — те же имена файлов, другая папка в ссылке.

### Как перенести на другую машину

Два варианта:

1. **Готовый пакет.** Скопируйте папки `models\` (модель и образцы) и `.venv\`
   (только если та же ОС и та же версия Python). Программа запустится сразу,
   без интернета.
2. **Инструкция.** Передайте проект без `models\` и `.venv\`, а на месте:

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\install_chatterbox.ps1          # только если нужен локальный голос
.\.venv\Scripts\python.exe tools\download_models.py   # заранее скачать модель
```

Для полностью офлайн-запуска после переноса: `set HF_HUB_OFFLINE=1`.

## Настройка голоса

Всё в правой панели окна, сохраняется в `config.json`:

- **Голос** — `ru-RU-DmitryNeural` (муж.), `ru-RU-SvetlanaNeural` (жен.);
  галочка «Показать все голоса» открывает остальные 320 голосов Edge.
- **Темп** — от −50 % до +50 %.
- **Громкость** — громкость самого синтеза.
- **Тон** — от −50 до +50 Гц (ниже — басовитее).
- **Плеер** — громкость воспроизведения на этом компьютере.
- **Читать не длиннее** — сколько символов ответа озвучивать.

## Голосовой ввод

> **Функция экспериментальная.** Голосовой ввод работает, но пока может
> ошибаться: путать слова, терять первое слово фразы, не срабатывать на
> спецслово. В следующих версиях распознавание, скорее всего, заметно
> улучшится. Ввод текстом всегда доступен и полностью надёжен — микрофон его
> не блокирует.

Можно не печатать: говорите — текст появится в поле ввода.

Сначала проверьте микрофон: панель **«Микрофон» → «Проверить микрофон…»**.
Там выбор устройства, живой уровень, запись 3 секунд, прослушивание и
распознавание. Если полоски не двигаются — выберите другое устройство или
разрешите Windows доступ к микрофону.

Диалог подсказывает шаги: модель распознавания грузится сразу при открытии
(первый раз до полуминуты, потом мгновенно), в статусе видно, что происходит.
Кнопка «Распознать» включается, когда модель готова и запись сделана.

| Режим | Что делает | Микрофон открыт |
|---|---|---|
| **Без микрофона** | голосовой ввод выключен | никогда |
| **По нажатию** (по умолчанию) | запись по клавише | только во время записи |
| **Слушать микрофон** | ждёт спецслово «элви» | постоянно |

**По нажатию.** Нажмите и удерживайте Ctrl+Space, говорите, отпустите —
текст появится в поле ввода. Комбинацию можно сменить в настройках.
Esc отменяет запись, клик по кнопке 🎤 делает то же самое для мыши.
Галочка **«Регистрировать нажатия глобально»** ловит клавишу, даже когда окно
MLVH не в фокусе; глобально Windows отдаёт только нажатие, поэтому там запись
включается и выключается повторным нажатием. Если комбинацию заняла другая
программа, MLVH честно скажет об этом и продолжит работать в окне.

**Отправлять сразу после распознавания** — галочка для тех, кто не хочет
жать Enter: распознанный текст сразу уходит в DeepSeek.

### Спецслово

Режим **«Слушать микрофон»** держит микрофон открытым и ждёт обращения:

> «Элви, в каком году было восстание декабристов?»

Услышав имя, MLVH пискнет и распознает фразу целиком — имя можно не повторять.
Можно и двумя частями: «Элви» → писк → «сколько времени?».

Пока MLVH говорит, микрофон не слушается (иначе он слышал бы сам себя);
это отключается галочкой `mute_while_speaking` в `config.json`.

**Про точность.** Имя «Элви» Vosk слышит приблизительно: «элвис», «элвин»,
«элли», «элби». MLVH сравнивает слова с допуском на одну опечатку, поэтому
все эти варианты ловятся, а «эльвира» — нет. Если имя всё равно плохо
ловится, поставьте спецсловом что-то попроще: «помощник», «слушай»,
«компьютер» — эти слова распознаются уверенно.

### Установка распознавания

По умолчанию голосовой ввод выключен: движок нужно поставить отдельно
(~50 МБ пакетов, модель скачается при первом распознавании).

```powershell
.\install_asr.ps1
.\.venv\Scripts\python.exe tools\check_asr.py   # что установилось
```

| Движок | Где работает | Русский | Модель |
|---|---|---|---|
| **faster-whisper** (по умолчанию) | GPU (CUDA), фолбэк на CPU | отличный, с пунктуацией | 75 МБ – 1.5 ГБ |
| **Vosk** | CPU, офлайн | средний, без пунктуации | 45 МБ |

Модель whisper выбирается в панели «Микрофон»: `tiny`, `base`, `small`
(по умолчанию), `medium` (~1.5 ГБ, точнее), `large-v3`. Файлы складываются
в `models\whisper\` (в git не попадают). Если CUDA не поднимется, MLVH сам
перейдёт на CPU — медленнее, но работает.

Если движок не установлен, кнопка микрофона неактивна с подсказкой, а всё
остальное работает как раньше.

## Агент: чтение файлов

> Пока только чтение. Записи, удаления и запуска команд нет.

Включение:

1. Панель **«Агент»** → галочка **«Чтение файлов»**.
2. **«Добавить папку…»** — можно несколько. Это единственные места, куда
   агент имеет доступ.
3. Спросите: «Что в файле notes.md?», «Найди, где упоминается …»,
   «Сколько строк в README?», «Сколько строк кода в проекте (только .py и .toml)?».

Что умеет:

| Инструмент | Что делает |
|---|---|
| `list_dir` | показать файлы и подпапки с размерами |
| `read_file` | прочитать текст постранично, с номерами строк |
| `search_text` | найти подстроку в файлах папки (без regex) |
| `count_lines` | посчитать строки в файлах с нужными расширениями |

`count_lines` не отдаёт содержимое файлов в контекст, пропускает служебные
каталоги (`.venv`, `.git`, `__pycache__`, `models`, `wheels`) и секреты, а
просматривает до 20 000 файлов — удобно для оценки размера проекта.

Агент сам решает, какой инструмент вызвать; в чате видны строки
«Агент: читаю …», а озвучивается только итоговый ответ. Содержимое файлов
вслух не читается. В строке статуса видно, сколько шагов сделано, сколько
файлов прочитано и какой размер окна модели.

### Границы и защита

- **Только чтение.** Ни записи, ни удаления, ни запуска команд.
- Пути проверяются после раскрытия `..` и симлинков: выход за папку — отказ.
- Нельзя открыть корень диска, `Windows`, `Program Files`, `ProgramData`.
- Секреты (`.env`, `*.key`, `*.pem`, `id_rsa`, `.ssh` …) не читаются и не
  показываются в списке даже внутри разрешённой папки.
- Двоичные файлы и файлы больше 50 МБ пропускаются; за одно чтение — до
  256 КБ и 400 строк.
- `count_lines` обрабатывает до 5000 подходящих файлов; при большем количестве
  результат помечается неполным.
- **Защита от зацикливания:** 20 шагов на вопрос (по умолчанию; в окне можно
  задать любое положительное число — жёсткого потолка нет), третий одинаковый
  вызов отклоняется, не больше 100 вызовов, 300 секунд, 800 000 символов данных.
  Если лимит сработал, MLVH делает один финальный запрос без инструментов,
  чтобы всё-таки ответить, и называет причину остановки со счётчиками: «лимит
  шагов (20 из 20)», «лимит вызовов (100 из 100)», «лимит времени (300 из 300 с)»,
  «лимит объёма данных» или «нет прогресса». Лимиты меняются в `config.json` →
  `agent`; для `--ask` число шагов задаёт ещё и `--agent-rounds N`.
- **Старые лимиты поднимаются сами.** Если в `config.json` остались значения
  из 0.3.0 (6 шагов, 12 вызовов, 120 с, 400 000 символов), при первом запуске
  они один раз заменяются на новые — править файл руками не нужно.

### Контекст

`model.context_tokens` — размер окна модели, по умолчанию **1 000 000**
(DeepSeek-V4.1). История обрезается по оценке токенов, а не по числу реплик;
старые сообщения уходят целиком, группа `tool_calls` + ответы `tool` не
разрывается. Запас под ответ — `model.max_tokens`. Если у выбранной модели
окно меньше 1M, уменьшите `model.context_tokens`: иначе DeepSeek отклонит
слишком длинный запрос.

Важно: содержимое прочитанных файлов **уходит в DeepSeek**. Не добавляйте
папки с тем, что не должно покидать компьютер.

### Проверка

```powershell
.venv\Scripts\python.exe tools\check_agent.py          # офлайн, без сети
.venv\Scripts\python.exe tools\check_agent.py --live   # живой запрос
python main.py --ask "Что в sample.txt?" --read-folder D:\docs
python main.py --ask "Сколько строк кода (.py и .toml)?" --read-folder D:\docs
```

`--ask` печатает строки инструментов и ответ в консоли, без окна и озвучки.

## Агент: интернет

> Только чтение: найти, открыть, прочитать, ответить. Кликов, форм, отправки
> данных и загрузок файлов нет.

Включение: панель **«Агент»** → галочка **«Интернет: поиск и чтение страниц»**.
Настройки читаются при старте, поэтому после изменения `config.json` или
включения галочки **перезапустите MLVH**. Для консоли: `--browse` разрешает
интернет на один запуск, даже если в настройках выключено; если интернет уже
включён галочкой, `--ask` использует его сам.

| Инструмент | Что делает |
|---|---|
| `search_web` | поиск в DuckDuckGo: заголовок, адрес, короткое описание |
| `open_page` | открыть страницу: заголовок, текст, ссылки, финальный адрес |

Поиск идёт через HTML-выдачу DuckDuckGo — API-ключ не нужен. Страницы качаются
стандартным `urllib`, HTML превращается в текст своим парсером (без внешних
пакетов). Если без JavaScript текста на странице нет, один раз запускается
установленный **Chrome** в headless-режиме (`--dump-dom`, виртуальное время):
так читаются SPA. Chrome ищется сам: `agent.chrome_path` в `config.json` →
переменная `MLVH_CHROME_PATH` → стандартные места → `PATH`.

Настройки в `config.json` → `agent`:

- `web_max_searches` (5), `web_max_pages` (10), `web_max_results` (8);
- `web_max_chars` (20 000) — сколько текста страницы уходит в контекст;
- `web_timeout` (15 с), `web_render` — `auto` / `always` / `never`;
- `web_proxy` — `auto` (российские домены напрямую, остальные через системный
  прокси), `system`, `direct` или адрес вида `http://127.0.0.1:10809`;
- `chrome_path` — если Chrome установлен нестандартно;
- `web_allow_local` — только для проверок на `127.0.0.1`.

### Границы и защита

- **Только `http` и `https`.** `file://`, `data:`, `javascript:`, `chrome://`,
  `ftp://` и адреса с логином/паролем закрыты.
- **Локальная сеть закрыта:** `localhost`, имена без домена, частные и
  служебные IP (`127.0.0.1`, `10.x`, `192.168.x`, `169.254.x`, `::1`) — иначе
  браузер обходил бы запрет на чтение файлов. Каждый редирект проверяется
  заново.
- Потолки: 5 поисков и 10 страниц на вопрос, 20 000 символов страницы в
  контекст; общие 20 шагов / 100 вызовов / 300 с / 800 000 символов.
- Загрузки не скачиваются, JS-диалоги не открываются, формы не заполняются.
- Содержимое страниц — **данные, а не инструкции**: если на странице написано
  «игнорируй правила» или «выполни команду», агент этого не делает.
- Каждый переход виден в чате строкой «Агент: открываю …»; озвучивается только
  итоговый ответ.
- `robots.txt` не проверяется: страницы открываются по прямому вопросу
  пользователя, как в обычном браузере; платные стены и капчи не обходятся.
- Текст страниц **уходит в DeepSeek** — не просите открывать страницы с личными
  данными и закрытой информацией.

### Проверка

```powershell
.venv\Scripts\python.exe tools\check_web.py          # локальный сервер + Chrome, без сети
.venv\Scripts\python.exe tools\check_web.py --no-chrome
.venv\Scripts\python.exe tools\check_web.py --live   # DuckDuckGo и example.com
.venv\Scripts\python.exe tools\check_agent.py --live --browse --question "Найди …"
```

`tools/check_web.py` поднимает свой `http.server` на `127.0.0.1`, подменяет
выдачу DuckDuckGo такой же разметкой и проверяет поиск, чтение, лимиты,
запреты и отрисовку JavaScript настоящим Chrome.

## Агент: MCP

> Внешние инструменты — отдельные программы на вашем компьютере. Они **не
> ограничены** папками агента и **могут менять данные**. Запускайте только
> те серверы, которым доверяете.

MCP (Model Context Protocol) — способ подключить к агенту чужие инструменты:
браузер, базы данных, файловые хранилища и т. п. MLVH работает как MCP-клиент
по stdio: запускает сервер, узнаёт список инструментов и вызывает их по
просьбе модели. Поддерживаются только инструменты (`tools`); prompts,
resources и sampling — нет.

Включение:

1. Панель **«Агент»** → галочка **«MCP-серверы (внешние инструменты)»**.
2. **«Добавить…»** — id, команда, аргументы, окружение, рабочая папка, таймаут.
3. **«Проверить сервер…»** — MLVH запустит сервер и покажет, сколько
   инструментов он отдал; ошибки (нет `npx`, сервер упал) видны сразу.
4. Спрашивайте как обычно: агент сам решит, какой инструмент вызвать.

Серверы подключаются при следующем вопросе, в фоновом потоке. Правки
`config.json` извне подхватываются после перезапуска MLVH. Для консоли:
`python main.py --ask "…" --mcp`.

Пример: Chrome DevTools MCP (клики и сессии в настоящем Chrome):

```json
"mcp_servers": [
  {
    "id": "chrome-devtools",
    "command": "npx",
    "args": ["-y", "chrome-devtools-mcp@latest"],
    "enabled": true,
    "timeout": 120
  }
]
```

`npx -y` обязателен: без `-y` установка пакета ждёт подтверждения. Первый
запуск скачивает пакет, поэтому `mcp_start_timeout` по умолчанию 120 с.
Серверы на `npx` требуют установленного Node.js LTS и npm.
Файловый сервер подключается так же: команда `npx`, аргументы `-y`,
`@modelcontextprotocol/server-filesystem`, `D:\docs`.

| Инструмент | Что делает |
|---|---|
| `mcp_<id>_<tool>` | вызов инструмента сервера `<id>`; полный список — в «Проверить сервер…» |

### Границы и защита

- Имена инструментов начинаются с `mcp_` — в чате всегда видно, что вызов
  внешний («Агент: MCP chrome-devtools: take_snapshot»).
- Лимиты те же, что у остальных инструментов: 20 шагов, 100 вызовов, 300 с,
  800 000 символов, третий одинаковый вызов отклоняется.
- Таймаут вызова — `agent.mcp_timeout` (60 с) или `timeout` сервера. При
  таймауте или падении процесс убивается вместе с деревом, сервер
  перезапускается один раз за вопрос, а вызов **не повторяется**: иначе
  действие могло бы выполниться дважды.
- Вывод сервера считается данными, а не инструкциями. Картинки и base64
  в DeepSeek не уходят: вместо них пометка вроде «[изображение image/png]».
- Ключ DeepSeek серверу не передаётся; свои токены задавайте в поле
  «Окружение» (`KEY=VALUE`).
- stderr сервера пишется в `logs/mcp.log` (в git не попадает), последние
  строки показываются в тексте ошибки.
- Содержимое, которое сервер вернул, **уходит в DeepSeek** — как и текст
  файлов и страниц.

### Проверка

```powershell
.venv\Scripts\python.exe tools\check_mcp.py                  # фейковый сервер, офлайн
.venv\Scripts\python.exe tools\check_mcp.py --config         # серверы из config.json
.venv\Scripts\python.exe tools\check_mcp.py --preset chrome-devtools
.venv\Scripts\python.exe tools\check_mcp.py --config --call mcp_demo_echo --args '{\"text\": \"привет\"}'
.venv\Scripts\python.exe tools\check_mcp.py --agent-live     # живой DeepSeek + фейковый сервер
```

В PowerShell кавычки внутри JSON экранируются обратной косой чертой (`\"`),
иначе argparse получит не тот набор аргументов.

`--preset chrome-devtools` скачивает npm-пакет при первом запуске — это
необязательная живая проверка. `--agent-live` проверяет, что DeepSeek
принимает MCP-схемы и вызывает инструмент.

## Как устроено

```
main.py                  запуск, режимы --say / --ask / --browse / --mcp / --agent-rounds / --list-voices / --persona
app/config.py            .env + config.json, dataclass-настройки, характеры
app/personas.py          встроенные характеры: промпт + пресет голоса
app/agent/               агент: политика папок, инструменты, контекст, цикл
app/agent/web.py         интернет: поиск DuckDuckGo, HTML→текст, Chrome для SPA
app/agent/mcp.py         MCP-клиент: JSON-RPC 2.0 по stdio, tools/list и tools/call
app/asr/                 распознавание: движки whisper/vosk, запись, хоткеи
app/deepseek_client.py   запрос к DeepSeek ([OI]-совместимый API), стриминг и tools
app/tts.py               edge-tts → mp3 → pygame, чистка markdown, нарезка на фразы
app/ui/main_window.py    окно на PySide6
app/ui/persona_dialog.py правка характера: имя, промпт, голос, темп, тон
app/ui/mcp_dialog.py     настройка MCP-сервера: команда, аргументы, окружение
app/ui/workers.py        QThread: чат, агент, список голосов, озвучка
```

Ответ приходит потоком и сразу печатается; озвучка начинается с первой фразы,
следующая синтезируется, пока звучит текущая.

### Скорость озвучки

Голос стартует, **не дожидаясь конца ответа**: как только модель выдала первую
фразу, она уходит в синтез, а остальной текст продолжает печататься.

- Первая фраза режется коротко (от 20 символов), дальше куски крупнее —
  у Edge TTS фиксированные ~1 с на запрос, поэтому длинные куски выгоднее.
- Синтез и проигрывание идут в разных потоках: пока звучит фраза N,
  уже готовится фраза N+1, паузы между ними нет.
- Повторы при отказе сервиса короткие (0.15 с), а не 0.5–1.5 с, как раньше.

Замеры (одинаковый текст, Edge TTS): до первого звука было **2.3 с**, стало
**1.3 с**; на длинных ответах выигрыш больше, потому что раньше приходилось
ждать весь текст целиком.

## Если что-то не так

- **401** — ключ неверный или удалён: введите заново.
- **402** — на балансе DeepSeek нет средств.
- **Нет связи с api.deepseek.com** — проверьте интернет/VPN/прокси.
- **`SSL: The handshake operation timed out`** — системный прокси или антивирус
  рвёт TLS. MLVH в режиме `auto` уже пробует второй путь; если ошибка осталась,
  поставьте `agent.web_proxy` = `direct` (совсем без прокси) или укажите рабочий
  `http://host:port`. Корневые сертификаты Windows подхватываются автоматически,
  но проверка TLS не отключается.
- **`CERTIFICATE_VERIFY_FAILED`** — сайт подписан корнем, которого нет ни в
  certifi, ни в хранилище Windows (например, `rbc.ru` с истёкшим сертификатом
  или `rzd.ru` с Russian Trusted Root CA). Такой сайт лучше открыть вручную:
  отключать проверку сертификатов MLVH не будет.
- **Список голосов не загрузился** — нет доступа к сервису Edge; остаются два
  голоса по умолчанию, синтез всё равно может работать.
- **Edge молчит** — сервис Microsoft иногда отвечает «No audio». MLVH делает
  4 попытки, затем читает ответ голосом Windows (SAPI), он работает офлайн.
- **Пустой ответ** — раньше случалось из-за режима рассуждений: reasoning съедал
  весь `max_tokens`, и контент приходил пустым. Теперь при пустом ответе MLVH
  автоматически повторяет запрос без рассуждений, а при обрезанном ответе пишет
  об этом в строке статуса. При включённых рассуждениях лимит поднимается
  минимум до 2000 токенов.
- **Не удалось воспроизвести звук** — нет аудиоустройства или занято другой программой.
- **MCP-сервер не запускается** — нажмите «Проверить сервер…»: ошибка покажет
  хвост stderr. Если в нём `must use TLS 1.2` или `The network path was not
  found`, проверьте `npm config get registry`: там должен быть `https://…`.
  Исправить: `npm config set registry https://registry.npmjs.org/`. Если сервер
  на `npx` долго стартует в первый раз, увеличьте `agent.mcp_start_timeout`.

## Ограничения

- **Контекст живёт только в пределах сессии.** `self.history` хранится в памяти:
  закройте окно — диалог начнётся заново. При смене характера история тоже
  очищается. В модель уходит системный промпт и история, обрезанная под
  `model.context_tokens` (по умолчанию 1M); старые сообщения отбрасываются.
- **Агент читает только текстовые файлы** в явно указанных папках (до 50 МБ)
  и отправляет их содержимое в DeepSeek. Двоичные файлы и секреты закрыты.
- **Агент в интернете видит только текст страниц.** Капчи, вход по паролю,
  PDF и видео остаются недоступны; Chrome нужен лишь для страниц на JavaScript,
  поэтому часть сайтов может ответить пустой страницей или блокировкой.
- **MCP-серверы — это сторонний код.** MLVH не проверяет, что они делают:
  правило «только чтение» на них не распространяется. Поддерживаются только
  stdio и только инструменты (`tools`); HTTP-серверы, prompts, resources
  и sampling — нет.
- **Chatterbox нестабилен на русском**: обрывает фразы, путает ударения.
  Это ограничение модели, а не кода. Для чистого произношения — Silero или Edge.
- **Silero — CC BY-NC 4.0**: нельзя использовать в коммерческих продуктах.
- Ввод текстом работает всегда; голосовой ввод требует установки
  `install_asr.ps1` и скачивания модели (первое распознавание — с ожиданием).
- Голосовой ввод пока **экспериментальный**: точность и срабатывание
  спецслова могут подводить. В следующих версиях улучшим.
- Спецслово «элви» Vosk слышит приблизительно (см. «Спецслово»): если не
  ловится, поставьте «помощник» или «слушай». Вопрос должен идти вместе
